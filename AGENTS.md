# AGENTS.md

## Cursor Cloud specific instructions

This repo is the `@cubic-plugin/cubic-plugin` package: a Node.js/TypeScript CLI (built with `citty`) that installs the cubic AI code-review plugin (skills, slash commands, and MCP config) into AI coding tools (Claude Code, Cursor, OpenCode, Codex, Gemini, Droid, Pi, universal). It is a client-side CLI — there is **no server, database, or long-running service** to start. External services it talks to (cubic MCP at `https://www.cubic.dev/api/mcp`, PostHog telemetry) are hosted; telemetry uses `posthog-js` with a baked-in project API key by default (`POSTHOG_API_KEY` overrides it, `POSTHOG_HOST` can redirect it, and setting `POSTHOG_API_KEY` to empty disables telemetry).

Standard commands live in `package.json` scripts: `npm run build` (`tsc`, emits to gitignored `dist/`) and `npm test` (builds, then runs `node --test test/*.test.mjs`). There is no linter configured.

Non-obvious notes:
- The compiled entrypoint is `dist/index.js`, so you must `npm run build` before running the CLI directly (`node dist/index.js install --help`). `npm test` builds first automatically.
- To exercise the installer without touching real editor config, pass `--output <dir>` (writes per-target under that dir) — e.g. `node dist/index.js install --to cursor --output /tmp/out`.
- Full installs write OAuth-ready MCP configs (no `Authorization` headers / no `CUBIC_API_KEY`). Users authenticate later via each editor's MCP login flow. `--skills-only` skips MCP entirely. Interactive TTY prompting is not required for MCP auth; `--json` mode works non-interactively without an API key.
- Default installs target home-directory agent roots. With `--to all` and no `--output`, undetected agents are skipped; pass `--to <target>` or `--force` as needed. Symlink installs from ephemeral `npx`/temp sources are mirrored into `~/.cubic-plugin/plugin-source`.
- `node scripts/validate-template.mjs` validates the plugin template/marketplace files (the "no hooks/hooks.json" line is an expected warning, not a failure).
- The CLI uses `posthog-js` (lazy init in `src/posthog.ts`). When `POSTHOG_API_KEY` is unset it uses the baked-in public project key; a non-empty value overrides that key, and an empty value disables telemetry. The test script sets `POSTHOG_API_KEY=` to prevent telemetry from reaching PostHog.
- Stripe Accounts v2 integration lives under `src/stripe/` and is exposed as `cubic-plugin stripe …` domain commands (`create-account`, `create-account-link`, `create-product`, `create-checkout-session`, `create-payment-intent`, `serve-payment`, `create-subscription-plan`, `attach-balance-payment-method`, `create-subscription`, `handle-webhooks`). The embedded PaymentElement flow (`create-payment-intent` / `serve-payment`) creates PaymentIntents with automatic payment methods and returns a transient `client_secret` that is never persisted to the store. Copy `.env.example` to `.env` and set `STRIPE_SECRET_KEY` / `STRIPE_PUBLISHABLE_KEY` from the Stripe Dashboard. Resource ids are persisted in `.cubic-stripe.json` (override with `CUBIC_STRIPE_STORE`). The Stripe client is initialized without a hard-coded API version.
- Board presentations live under `presentations/` (currently `apple-fy2025-environmental/`). They are static HTML (`index.html` + `styles.css` + `deck.js` IIFE) plus a Python exporter (`generate_pptx.py` → `Apple_FY2025_Environmental_Progress.pptx`). `python-pptx` is not an npm dependency; the directory is not in `package.json` `files`. HTML and PPTX are dual sources of truth (no shared data file). `deck.js` has no hash routing; swipe threshold is 50px; notes visibility is sticky across slides. Do not add a CLI command or Node build for the deck unless the code grows one.
